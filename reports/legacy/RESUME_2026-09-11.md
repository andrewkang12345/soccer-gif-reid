## Where the reference images are

The actual reference files are at:

```
/mnt/data/soccer_gif_reid/data/MuPNIT-ReID/gallery/
  player_0001/   # Al Horford
  player_0002/   # Alec Burks
  ...
```

The archive README identifies these as images sourced outside the MOT videos. Inspected examples include portraits, publicity images and action photos, sometimes with watermarks, another player, or an unusual pose. Thus the whole gallery should not be assumed to be a clean, isolated-headshot collection. See [actual reference examples](mupnit_reference_preview.jpg); the exact preview filenames are in `mupnit_reference_preview.json`.

The original ID/name source is `data/MuPNIT-ReID/global_local_player_descriptions_final_v5.json`. A convenient directory/count/name index is now saved at `data/mupnit_gallery_identities.json`.

`RosterMatcher` in `src/soccer_gif_reid/infer.py` loads a supplied `--roster` image directory. It embeds all reference images, averages normalized image embeddings for each identity into a normalized reference centroid, then ranks identities by cosine similarity to a new crop (or mean per-frame similarity for a tracklet). Folder names provide output identity labels; the metadata/index maps MuPNIT folder IDs to names. These similarities are not calibrated probabilities.

For soccer deployment, the roster directory must contain independent soccer reference photos, e.g. `roster/Lionel_Messi/headshot.jpg` and `roster/Lionel_Messi/full_body.jpg`. **No such soccer gallery is configured in this experiment yet.** The existing Argentina–France metadata in `sports_reID/sample_data/test_metadata.json` contains names/numbers, but no `headshot_path` entries. NBA gallery images train/evaluate the representation; soccer roster images define the candidate identities during soccer inference.
